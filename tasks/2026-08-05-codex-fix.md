# Codex 审核修复: 3 个 MEDIUM 缺陷

## NP-RV-001 — 端口遍历缺少稳定排序

**文件:** `src/backend/Datacenter.Api/Controllers/NetworkPathController.cs`

**问题:** BFS 中 `srcPorts` 和 `curPorts` 来自未排序的 `ToListAsync()`，当源设备有多个端口时，等长路径的选择可能不具确定性。

**修复:** 在构建 `serverToPorts` 时对端口排序（第 64-66 行）。将：
```csharp
var serverToPorts = ports
    .GroupBy(p => p.ServerId)
    .ToDictionary(g => g.Key, g => g.ToList());
```
改为：
```csharp
var serverToPorts = ports
    .GroupBy(p => p.ServerId)
    .ToDictionary(g => g.Key, g => g.OrderBy(p => p.Id).ToList());
```
仅此一处改动即可，因为所有端口遍历都通过 `serverToPorts` 取值。

## NP-RV-002 — 无路径结果缺少 warning 提示

**文件:** `src/frontend/src/components/NetworkPathDrawer.vue`

**问题:** warning 横幅只在 `pathFound=true` 时显示。后端无论是否找到路径都返回 `warning` 字段。

**修复:** 将 warning banner（第 216-218 行）从 `v-if="pathResult.pathFound"` 的 div 内移到外面。具体：

将这段：
```html
<template v-else-if="pathResult">
  <div v-if="pathResult.pathFound" class="warning-banner" role="status">
    ⚠ {{ pathResult.warning }}
  </div>

  <div v-if="!pathResult.pathFound" class="no-path">
```
改为：
```html
<template v-else-if="pathResult">
  <div class="warning-banner" role="status">
    ⚠ {{ pathResult.warning }}
  </div>

  <div v-if="!pathResult.pathFound" class="no-path">
```
即：warning banner 始终显示，只要 `pathResult` 存在。

## NP-RV-003 — 设备选择器不显示机柜

**文件:** 
- `src/backend/Datacenter.Api/Controllers/ServersController.cs`
- `src/frontend/src/components/NetworkPathDrawer.vue`

**问题:** 下拉标签没有机柜编号。GET /api/servers 不返回 rackCode。

**修复分两步:**

### 步骤 1: 后端 ServersController 补充 rackCode

在 `src/backend/Datacenter.Api/Controllers/ServersController.cs`，修改第 60-74 行的 Select 投影，补充 rackCode 字段：

```csharp
var servers = await query
    .Select(server => new
    {
        server.Id,
        server.Name,
        server.ManagementIP,
        server.AssetNumber,
        server.DeviceType,
        server.DeviceHeight,
        server.OperationalStatus,
        server.PositionStatus,
        server.System,
        server.Owner,
        server.Notes,
        RackCode = dbContext.ServerPositions
            .Where(sp => sp.ServerId == server.Id && sp.Status == "在架")
            .Select(sp => sp.Rack.Code)
            .FirstOrDefault()
    })
    .ToListAsync(cancellationToken);
```

参考 `PortsController.cs` 中已有的 `ConnectedToRackCode` 查询模式（相同手法）。

### 步骤 2: 前端 NetworkPathDrawer 显示机柜

**2a.** 在 `ServerOption` 接口中加 `rackCode` 字段（第 34-38 行）：
```ts
type ServerOption = {
  id: string
  name: string
  deviceType: string
  positionStatus: string
  rackCode: string | null
}
```

**2b.** 在 `parseServerOption()` 中解析 rackCode（第 105-117 行），加一行：
```ts
rackCode: typeof r.rackCode === 'string' ? r.rackCode : null,
```

**2c.** 修改 `serverLabel()` 函数（第 92-95 行），改为：
```ts
function serverLabel(s: ServerOption): string {
  const rackHint = s.rackCode ? ` - ${s.rackCode}` : ' - 未上架'
  return `${s.name} (${s.deviceType})${rackHint}`
}
```
