## 1. 用户目标

- [事实] 用户希望现有线缆拓扑不只显示机房之间的汇总链路，还能下钻到设备到设备、端口到端口的连接。
- [事实] 用户希望页面具有 2.5D 视觉层次，但不采用成本和运行负担更高的完整 3D。
- [事实] 用户希望线路具有可见的动态流向效果。
- [推断] 用户真正需要的是更直观地回答“某设备通过哪个端口、哪条线缆连接到哪台设备”，而不是建设实时网络监控平台。
- [建议] MVP 应围绕“登记拓扑的设备级可视化和路径追踪”交付，不扩大为实时流量、链路性能或告警监控系统。

## 2. 图稿的文字化描述

### 2.1 整体布局

- [事实] 图稿采用深蓝黑色运维大屏风格，页面保持现有系统的左侧导航、顶部标题区、主画布和右侧详情区。
- [事实] 左侧导航包含：首页、机房管理、服务器管理、线缆管理、拓扑地图；拓扑地图处于选中状态。
- [事实] 顶部标题为“机房线缆拓扑”，并显示“全部机房 / 上海机房 / A区 / 设备链路”层级路径。
- [事实] 顶部操作区包含“2.5D视图”“筛选”“自动布局”“流向动画”。
- [事实] 画布右上方提供“机房级”“机柜级”“设备级”切换，图稿中选择“设备级”。
- [事实] 中间主画布显示一个机房区域、四个机柜、多个设备、设备端口和设备之间的线路。
- [事实] 左下角显示线路类型及单向、双向流向图例。
- [事实] 右侧固定面板显示选中线路的设备、端口、类型、状态、带宽、流向和路径。

### 2.2 画布层次

- [事实] 画布背景为低对比度网格，设备和线路位于网格上方。
- [事实] 机房区域以轻微等距透视的抬高底板呈现，形成 2.5D 层次。
- [事实] 机柜使用带顶面、正面和轻微阴影的卡片式外观，不允许自由旋转镜头。
- [事实] 设备以机架式设备条或独立设备卡片呈现，设备名称始终可见。
- [事实] 端口以设备边缘的小型锚点和端口标签呈现。
- [建议] 2.5D 只用于建立视觉层级，不改变业务坐标、设备 U 位和端口连接模型。

### 2.3 图稿示例节点

- [事实] 图稿示例包含机柜 R3-01、R3-02、R3-03、R3-04。
- [事实] 图稿示例包含 APP-01、APP-02、DB-01、DB-02、SW-CORE-01、SW-CORE-02、FW-01、STORAGE-01、BAK-01。
- [事实] 图稿示例端口包含 eth0、eth1、GE0/0、GE0/1、GE0/2、GE0/3、FC1、FC2。
- [建议] 正式页面必须使用接口返回的真实机房、机柜、设备和端口数据，不得把上述示例名称硬编码到业务代码。

### 2.4 图稿示例链路

- [事实] 图稿以发光线路连接具体设备端口。
- [事实] 图稿通过箭头、亮点和高亮轨迹表达线路方向。
- [事实] 青色、紫色、橙色和红色线路分别承担不同网络用途或状态的视觉区分。
- [事实] 选中线路比其他线路更亮，未选中线路降低透明度。
- [建议] 正式页面应优先突出用户当前选择的单条线路或路径，避免一次显示全部 412 条线缆造成线路拥挤。

## 3. 当前项目事实

### 3.1 已有前端基础

- [事实] 当前拓扑入口为 /topology，对应 src/frontend/src/views/TopologyView.vue。
- [事实] 当前拓扑使用 Vue 3、TypeScript 和 Konva 10.3.0。
- [事实] 当前 TopologyView 已实现机房级和机柜级两种模式。
- [事实] 当前机房级支持机房节点、跨机房聚合线路、悬浮提示、管理员拖拽并保存机房拓扑坐标。
- [事实] 当前机柜级支持机柜节点、跨机柜聚合线路和线路悬浮提示。
- [事实] 当前 useTopology.ts 的模式仅为 rooms 或 racks，不包含 devices。
- [事实] 当前拓扑颜色由线缆类型映射，已定义铜缆、光纤、DAC、网线。
- [事实] 当前 CableLayer.vue 已具有虚线流动动画、箭头、路径高亮和 prefers-reduced-motion 降级处理。
- [事实] 当前 useCableScene.ts 已定义 room、rack、device、port 四级焦点模型，并包含设备边缘锚点、跨机柜路径、同机柜路径、筛选、图例、详情和面包屑逻辑。
- [事实] 当前 FloorplanCanvas.vue 中 cable-scene 加载函数首行直接 return，线缆场景在该入口处暂时禁用。
- [事实] 当前 RackDeviceView.vue 已能加载 cable-scene、选择设备或端口焦点，并查询网络路径。
- [建议] 设备级拓扑应优先复用 useCableScene.ts、CableLayer.vue、NetworkPathDrawer.vue 和 SwitchPortDrawer.vue 的已有能力，避免在 TopologyView 中重复实现第二套线路模型。

### 3.2 已有后端基础

- [事实] GET /api/rooms/topology 提供机房级和指定机房的机柜级聚合拓扑。
- [事实] GET /api/rooms/{roomId}/cable-scene 提供机柜、设备和线缆场景数据。
- [事实] cable-scene 当前只把设备类型包含交换、switch、路由、router、网络或 network 的在架设备加入 devices 集合。
- [事实] cable-scene 返回线缆 ID、线缆类型、用途，以及两端设备 ID、设备名称、端口名称、机柜 ID 和机柜编码。
- [事实] GET /api/network-path 根据起点和终点设备返回已登记连接路径、设备列表和每一跳端口。
- [事实] network-path 的返回信息明确提示“已登记连接拓扑示意，不代表实时数据包路由”。
- [事实] Server 模型包含设备名称、设备类型、运行状态、位置状态、设备高度等信息。
- [事实] Port 模型包含端口名、端口类型和可选速率。
- [事实] Cable 模型包含源端口、目标端口、线缆类型、颜色、长度、备注和 Purpose。
- [事实] 当前 Cable 模型没有实时链路状态、实时流量、利用率、时延、丢包率或实际数据包方向字段。
- [事实] 当前 Cable 的 SourcePort 和 TargetPort 表示登记连接的两端，不能自动证明实际网络流量方向。
- [事实] 当前数据库已具备设备、端口和线缆之间的关联关系，不需要为了展示登记拓扑重新设计基础实体。

## 4. 与现有项目规则的冲突

- [事实] AGENTS.md 将“实时线缆动画”列为第一阶段禁止范围。
- [事实] 图稿要求线路具有动态流向显示。
- [推断] 若“流向动画”仅表示已登记线缆的视觉方向，不读取实时流量数据，它与“实时监控动画”不是同一产品能力。
- [推断] 即使采用视觉动画，SourcePort 到 TargetPort 也只能表示登记顺序，不能宣称为实际数据包方向。
- [事实] 用户于 2026-08-11 明确选择将两项效果组合使用：所有线路保留静态箭头和路径高亮；选中线路允许使用纯前端装饰性流动动画。
- [事实] 用户明确要求使用装饰性动画时同时显示“非实时流量”提示。
- [建议] Claude + DeepSeek 不再把静态箭头与选中线路动画作为二选一，应在产品裁决中保留上述组合要求，并书面解决它与“实时线缆动画”禁止项之间的语义边界。
- [事实] 当前 TASK-20260810-000003 仍处于开发中，且当前范围是机房级和机柜级拓扑。
- [事实] 新增设备级模式、可能修改 API 契约或扩大数据范围属于当前任务之外的新范围。
- [建议] Claude 批准产品范围后，应由技术角色判断是作为 TASK-20260810-000003 的正式 Change Request，还是另建后续任务。
- [建议] 在书面批准前，Cursor 不应开始修改 TopologyView、API 或数据模型。

## 5. 建议的 MVP 产品范围

### 5.1 必须实现

- [建议] 在现有 /topology 页面增加“设备级”下钻入口。
- [建议] 用户先选择一个机房，再进入设备级，不允许初始页面一次加载所有机房的全部设备。
- [建议] 设备级画布显示当前机房内的机柜和全部在架设备。
- [建议] 每个设备显示名称、设备类型、所在机柜和 U 位范围。
- [建议] 设备之间的已登记线缆连接到具体端口锚点。
- [建议] 点击设备后，只高亮与该设备直接相关的线路。
- [建议] 点击端口后，只高亮该端口对应的线缆。
- [建议] 点击线路后，右侧显示源设备、源端口、目标设备、目标端口、线缆类型、用途、端口速率和所在机柜。
- [建议] 非选中线路降低透明度，但仍保留整体关系。
- [建议] 画布支持平移、缩放、适应屏幕和返回机柜级。
- [事实] 页面必须保留“非实时流量”的显著说明。
- [建议] 线路较多时支持按现有 CableType 和 Purpose 筛选。
- [事实] 所有线路始终使用静态箭头表达登记方向；选中线路可以叠加装饰性流动动画和路径高亮。
- [建议] 动画关闭或系统启用 reduced motion 时，只停止装饰性运动，静态箭头和路径高亮必须保留。

### 5.2 明确不实现

- [建议] 不实现实时流量、带宽利用率、时延、丢包率和告警采集。
- [建议] 不实现完整 3D、自由旋转镜头、Three.js 场景或高精度设备模型。
- [建议] 不实现全机房所有设备同时展开。
- [建议] 不实现自动发现网络设备、SNMP、LLDP、交换机配置读取或监控平台集成。
- [建议] 不新增与当前验收无关的数据表、通用拓扑引擎、插件系统或布局框架。
- [建议] 不把图稿中的 APP-01、DB-01 等示例数据写死到项目。
- [建议] 不为追求图稿外观而重做整个系统导航和所有页面主题。
- [建议] 不把生成的整页 PNG 或 WebP 作为可交互页面背景。

## 6. 视觉规格

### 6.1 页面结构

| 区域 | [建议] 规格 |
|---|---|
| 左侧导航 | [建议] 复用现有 App 导航，不增加新的一级菜单。 |
| 顶部标题 | [建议] 标题为“机房线缆拓扑”，副标题明确为“登记连接拓扑示意，非实时流量”。 |
| 层级切换 | [建议] 显示“机房级 / 机柜级 / 设备级”，当前层级使用主色描边和深色背景。 |
| 工具栏 | [建议] 最少包含返回上级、筛选、自动布局、适应屏幕和动画开关。 |
| 主画布 | [建议] 占可用宽度主体，右侧详情打开时自适应缩小，不被详情面板覆盖。 |
| 左下图例 | [建议] 显示当前实际存在的线缆类型或用途，不展示数据库中不存在的分类。 |
| 右侧详情 | [建议] 默认收起；选择设备、端口或线路后打开；关闭后保持当前画布焦点。 |

### 6.2 2.5D 机房和机柜

- [建议] 使用 Konva Rect、Line、Path、Group 和阴影构建轻量 2.5D，不新增 Three.js。
- [建议] 机房底板使用深色网格、轻微透视边缘和低强度阴影。
- [建议] 机柜由正面矩形、窄顶面和侧面组成，保持设备 U 位从上到下可读。
- [建议] 机柜标题显示真实机柜编码。
- [建议] 停用机柜降低饱和度，不能只依靠颜色表达状态。
- [建议] 设备节点应优先使用可缩放的 Konva 图形和文本；只有确有必要时才增加少量透明 WebP 装饰素材。
- [建议] 2.5D 效果不得使端口锚点偏离实际设备位置。

### 6.3 设备节点

- [建议] 设备节点最少显示设备名称。
- [建议] 悬浮或选中时补充设备类型、运行状态、机柜编码、StartU-EndU 和关联线路数量。
- [建议] 交换机、服务器、存储、防火墙可以使用不同的简化轮廓，但不能依赖用户识别复杂图片。
- [建议] 正常、异常、维护状态同时使用颜色和文字或图标。
- [建议] 设备名称过长时省略显示，悬浮提示显示完整名称。
- [建议] 未选中状态下不展开所有端口标签，避免设备较多时文字重叠。

### 6.4 端口锚点

- [建议] 线路端点必须落到具体设备的端口锚点，不能只连接机柜中心。
- [建议] 默认只显示有线缆的端口锚点。
- [建议] 选中设备后显示该设备全部端口；选中端口后突出该端口及对端端口。
- [建议] 端口标签优先显示 PortName，详情面板补充 PortType 和 Speed。
- [建议] 同一设备端口较多时允许在设备边缘聚合，点击后再展开，MVP 不要求展示交换机全部物理端口面板。

### 6.5 线路

- [建议] 普通线路宽度为 2 px 左右，选中线路为 3 至 4 px。
- [建议] 未选中线路透明度降低到约 0.15 至 0.30，选中线路保持 0.9 以上。
- [建议] 线路使用圆角折线或平滑曲线，并尽量避开设备名称。
- [建议] 同一机柜内的线路从机柜侧边绕行，跨机柜线路使用中间路由通道。
- [建议] 线路交叉无法避免时，通过选中高亮和非选中弱化保证可读性，不引入复杂自动布线引擎。
- [建议] 页面颜色应由真实 CableType 或 Purpose 映射生成。
- [事实] 图稿中的“管理网络、业务网络、存储网络、告警链路”与当前 CableType/Purpose 字段值不完全一致。
- [建议] MVP 不应伪造这些分类；Claude 如要求完全采用图稿分类，必须先裁定数据来源和字段语义。

### 6.6 流向表现

- [事实] 所有线路在线路中段显示静态方向箭头。
- [事实] 选中线路允许叠加纯前端装饰性流动动画和路径高亮，可使用移动虚线偏移或少量粒子。
- [事实] 装饰性动画只作用于选中线路，不让全部线路持续运动。
- [建议] 动画开关默认记忆仅限当前页面会话，MVP 不需要新增用户偏好存储。
- [建议] prefers-reduced-motion 为 reduce 时必须关闭持续动画。
- [事实] 页面必须显示“非实时流量”提示，并把箭头语义描述为“登记端点方向”或“路径展示方向”，不能标记为实时数据流向。
- [建议] 双向链路只有在业务数据明确提供双向语义时才显示双向箭头；不能仅根据物理网线通常可双向通信进行猜测。

## 7. 交互规格

### 7.1 层级导航

- [建议] 机房级双击或点击“查看机柜”进入机柜级。
- [建议] 机柜级双击机柜或点击“查看设备”进入设备级。
- [建议] 面包屑允许返回机房级或机柜级。
- [建议] 浏览器返回键和页面返回按钮应保持一致结果。
- [建议] 切换层级时保留已选机房，不重新跳到全局首页。

### 7.2 设备选择

- [建议] 单击设备将其设为焦点。
- [建议] 焦点设备使用主色描边和轻微外发光。
- [建议] 与焦点设备无关的设备降低透明度，但名称仍可辨认。
- [建议] 与焦点设备直接相连的线路保持可见。
- [建议] 再次点击画布空白区域清除焦点。

### 7.3 线路选择

- [建议] 线路命中区域应宽于可见线条，便于鼠标点击。
- [建议] 单击线路打开右侧详情。
- [建议] 详情显示源设备、源端口、目标设备、目标端口、CableType、Purpose、端口 Speed、机柜编码。
- [建议] 如果 Speed 缺失，显示“未登记”，不能展示图稿示例中的固定 10 Gbps。
- [建议] 如果没有实时状态字段，状态显示“已登记”或省略，不能固定显示“正常”。
- [建议] 线路悬浮只显示简短摘要，完整内容放在右侧面板。

### 7.4 路径查询

- [建议] 用户选择起点设备和终点设备后，可调用现有 /api/network-path。
- [建议] 查询成功后按 hops 顺序高亮完整路径。
- [建议] 路径详情逐跳显示设备、端口、线缆类型和机柜。
- [建议] 未找到路径时显示接口返回的 Reason。
- [事实] 当前路径算法和接口只表示登记连接路径。
- [建议] 页面必须保留接口返回的 Warning，不得使用“真实路由”“实时路径”等表述。

### 7.5 筛选和大数据量

- [建议] 筛选最少支持 CableType 和 Purpose。
- [建议] 默认只加载当前机房。
- [建议] 默认优先显示机柜和设备，线路可按用户选择逐步显现。
- [建议] 当前数据量为 12 个机房、21 个机柜、344 台服务器、21 台交换机和 412 条线缆，设备级页面不能默认同时展开全量数据。
- [建议] MVP 先采用焦点弱化、类型筛选和当前机房范围控制，不引入复杂图数据库或自动拓扑布局服务。

## 11. 建议验收标准

### AC-01 层级进入

- [建议] Given 用户已登录并进入拓扑地图，When 用户选择一个机房并进入设备级，Then 页面只加载并显示该机房的机柜和在架设备。

### AC-02 设备可识别

- [建议] Given 设备级画布已加载，Then 每个设备至少显示真实名称，并可通过悬浮或选中查看设备类型、状态、机柜和 U 位。

### AC-03 端口级连接

- [建议] Given 两台设备之间存在已登记 Cable，Then 线路必须连接到两端设备的具体端口锚点，详情必须显示真实端口名。

### AC-04 设备焦点

- [建议] When 用户点击一台设备，Then 该设备及直接相关线路高亮，非相关线路降低透明度。

### AC-05 线路详情

- [建议] When 用户点击一条线路，Then 右侧显示真实源设备、源端口、目标设备、目标端口、CableType、Purpose、端口 Speed 和机柜信息；缺失值显示“未登记”。

### AC-06 路径查询

- [建议] When 用户选择起点和终点并查询路径，Then 页面按 /api/network-path 返回的 hops 顺序高亮登记路径，并显示“非实时数据包路由”提示。

### AC-07 流向语义

- [建议] Then 页面不得把 SourcePort 到 TargetPort 的登记方向描述为实际流量方向。
- [事实] Then 所有线路始终显示静态箭头，选中路径同时显示路径高亮。
- [事实] Then 选中路径允许显示装饰性流动动画，并提供关闭开关。
- [事实] Then 页面显著显示“非实时流量”提示。

### AC-08 动画可访问性

- [建议] Given 操作系统启用 prefers-reduced-motion，Then 持续流动动画停止，静态箭头仍然可见。

### AC-09 数据量控制

- [建议] Given 当前机房线缆较多，Then 页面支持按 CableType 或 Purpose 筛选，并避免默认同时显示所有机房设备。

### AC-10 无新增沉重依赖

- [建议] Then 实现继续使用 Vue 3、TypeScript 和现有 Konva，不新增 Three.js 或新的图可视化框架。

### AC-11 回归

- [建议] Then 现有机房级、机柜级拓扑、房间拖拽保存、线缆提示和权限行为继续通过原有测试。
