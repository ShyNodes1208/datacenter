# Windows 本地开箱即用部署基线（B 方案）

## 1. 状态与来源

- 状态：已确认的未来部署基线；**尚未创建实施任务，未修改应用代码**。
- 需求来源：用户于 2026-08-27 确认采用 B 方案，并要求在实际部署时按本文执行。
- 适用版本：当前 `datacenter` 单体应用及其后续功能。
- 目标平台：Windows 10 x64 本地单机使用。

本文定义交付目标和验收边界，不替代后续实施任务的详细设计、测试记录和审核。

## 2. 用户可见结果

用户下载并运行一个 Windows 安装程序。安装完成后从开始菜单或桌面快捷方式打开“机房管理系统”，系统自动在默认浏览器中打开本地页面。

用户不需要自行安装或使用：Node.js、npm、.NET SDK/Runtime、WSL、Python、数据库服务或命令行。

## 3. 已确认的 B 方案

### 3.1 运行形态

1. 发布物为 Windows 安装程序，目标为 `win-x64`。
2. 安装程序部署一个自包含（self-contained）的 .NET 应用；所需 .NET 运行环境随发布物提供。
3. 应用启动后仅在本机回环地址（`127.0.0.1`）提供前端页面和 `/api`；随后自动用默认浏览器打开本地地址。
4. 前端与 API 必须同源托管，保留现有前端相对 `/api` 请求和 Cookie 认证模型。
5. 用户关闭应用后，本地服务停止；不安装 Windows 服务，不对局域网提供访问。

### 3.2 用户侧依赖

| 项目 | 用户是否需要单独安装 | 说明 |
|---|---|---|
| Node.js / npm | 否 | 仅用于开发和构建，不进入安装版。 |
| .NET Runtime | 否 | 由自包含发布物携带。 |
| WSL / Python / SQLite | 否 | 不作为用户运行依赖。SQLite 由应用内部使用。 |
| 浏览器 | 否 | 使用 Windows 10 自带或已有默认浏览器，不引入 WebView2 或 Electron。 |

## 4. 数据与升级规则

1. SQLite 数据库不得写入 `Program Files`、安装包目录或当前工作目录。
2. 数据库、WAL/SHM 文件和可恢复备份必须存放在当前 Windows 用户的 `%LocalAppData%\Datacenter` 下。
3. 首次启动时应用创建数据目录并执行现有 EF Core 迁移。安装过程必须通过一次性、安全方式创建首个管理员；不得把开发账号 `admin/admin123`、任何默认密码或初始化密码写入安装包、源代码或日志。管理员创建成功后必须清除初始化密码。
4. 当前 `BootstrapAdmin` 仅在 Development 环境运行；后续部署任务必须实现上述受控初始化方式，但不得借此扩大为用户管理、注册或密码重置功能。
5. 升级前必须先创建可恢复的数据库备份；升级失败时必须保留原数据库和备份，不能静默覆盖。
6. 卸载默认保留用户数据；删除数据必须由用户在卸载流程中明确选择。

## 5. 后续实施的最小范围

后续创建独立部署任务时，只实现下列事项：

1. 生成前端生产构建，并将其作为后端静态文件随发布物提供；Vue 路由刷新必须正确回退到前端入口，`/api` 请求不得被回退规则拦截。
2. 将数据库路径改为上述用户数据目录，并加入升级前备份。
3. 提供本机回环监听、自动打开默认浏览器和正常退出的启动器行为。
4. 生成 `win-x64` 自包含发布物及 Windows 安装程序、开始菜单/桌面快捷方式和卸载项。
5. 建立可重复的 Windows 验收流程；不引入 Electron、WebView2、Docker、Windows 服务或远程数据库。

安装工具的具体选择（例如 Inno Setup 或 WiX）由实施任务在不增加用户运行依赖的前提下决定；不得仅为此引入新的应用运行框架。

## 6. 验收标准

在一台未安装 Node.js、.NET、WSL、Python 或数据库服务的干净 Windows 10 x64 环境中：

1. 用户可通过单一安装程序完成安装，无需命令行。
2. 从快捷方式启动后，浏览器在 15 秒内打开本地登录页。
3. 登录、机房/机柜/设备查看，以及现有新增、编辑、移动和导入功能均可用；前端不会再依赖 Vite 开发服务器。
4. 重启应用后数据仍存在；升级后数据仍存在且可恢复；卸载默认不删除数据。
5. 应用不监听局域网地址，其他设备无法直接访问本机 API。
6. 安装、启动、升级和卸载过程不改写源代码仓库、不要求 WSL，且不影响后续新功能开发。

## 7. 后续功能兼容约束

后续功能默认继续满足本地单机、同源前后端和 SQLite 本地存储的部署形态。任何需要远程访问、Windows 服务、独立数据库、额外桌面壳或用户自行安装运行时的功能，必须先单独提出变更请求并说明用户价值、依赖、数据迁移和运维影响。
