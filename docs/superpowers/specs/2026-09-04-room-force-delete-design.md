# 机房强制删除设计

## 目标

允许管理员/运维在首页**强制删除整个机房及其下属数据**，以便反复导入测试，无需逐条清理机柜/设备/服务器/线缆。

用户确认（2026-09-04）：强制删除时，只属于该机房的服务器**一并硬删**（方案 A）。逐条增删改机柜/设备/服务器/线缆暂不做，待本功能验证后再决定。

## 用户可见效果

- 首页机房卡片：空机房仍用现有「删除」；有机柜时显示「强制删除」（危险样式）。
- 强制删除前要求用户在 `prompt` 中输入机房**全名**（与卡片名称完全一致）；取消或名称不符则不发请求。
- 成功后刷新首页列表与汇总；机房及下属数据不可再查到。

## API 契约

扩展现有：

`DELETE /api/rooms/{id}?force=true`

| 条件 | 行为 |
|------|------|
| 无 `force` 或 `force=false` | 与现网一致：有机柜 → 409 `机房中存在机柜，不能删除`；无机柜 → 204 |
| `force=true` | 级联硬删后 204 |
| 机房不存在 | 404 |
| 非管理员/运维 | 403 |
| 缺 CSRF | 400 |

权限、CSRF 与现有 `Delete` 相同。不新增路径、不改表结构、无迁移。

## 级联删除顺序

外键均为 `Restrict`，必须按依赖手动删除：

1. 该机房全部 `Racks`
2. 这些机柜上出现过的全部 `ServerPositions` 对应的 `Server` Id 集合（含「已下架」历史）
3. 对这些服务器：`Cables`（源或目标端口属于这些服务器）→ `Ports` → `AuditRecords` → `ServerPositions` → `Servers`
4. 这些机柜的 `DevicePositions` → `Racks` → `Room`

跨机房线缆：任一端端口属于本机房将被删除的服务器，整条线缆删除（测试清库可接受）。

单事务：一次 `SaveChangesAsync`（或等价事务）完成；中途失败则整单回滚。

## 前端

- 修改 `HomeView.vue`：按 `rackCount` 分支按钮；强制删除调用 `DELETE /api/rooms/{id}?force=true`。
- 确认文案须明确「将永久删除机柜、设备、服务器、线缆等，不可恢复」。
- 不新增页面/路由/依赖。

## 非目标

- 逐条修改/删除机柜、设备、服务器、线缆
- 全库 Reset（已有 `Reset-Datacenter-Data.bat`）
- 软删除、回收站
- 为本功能单独写审计业务表（可选：不要求；删除服务器时其既有 AuditRecords 随级联清掉）
- 改 API 契约其它端点；改导入逻辑

## 验收标准

1. 空机房：普通删除仍 204，机房消失。
2. 非空机房：普通删除仍 409；`force=true` 后机房、机柜、设备 U 位、相关服务器/端口/线缆/审计/占位均消失。
3. 只读角色强制删除仍 403。
4. 前端：名称输错或取消不发请求；成功后列表刷新。
5. 后端集成测试覆盖上述关键路径；相关前端测试更新；`typecheck` / 目标测试通过。
